# Link Exchange MVP — בדיקת דופק

MVP לבדיקת ביקוש: מקדם אתרים נרשם עם מייל אחד ורשימת דומיינים (הדבקה או
קובץ CSV). המערכת סורקת כל אתר (לא רק עמוד הבית), מנחשת קטגוריה, בודקת
חוזק/ספאם/תעבורה, ומציגה הכל למסך אישור מרוכז אחד. אחרי האישור כל אתר
נכנס לתור התאמות יומי — מדי יום המערכת מנסה למצוא לו הצעת קישור חדשה
מול אתר אחר באותה נישה ובעוצמה דומה. שני הצדדים מאשרים לפני שנחשפים פרטי
קשר; הביצוע בפועל (הוספת הקישור) נשאר אצל בעלי האתרים, אבל המערכת בודקת
אוטומטית — וחוזרת ובודקת — שהקישור אכן עלה ונשאר באוויר.

## למה זה בנוי ככה

- **בלי DB חיצוני.** האחסון הוא קבצי JSON (`data/*.json`) כדי ש-`npm install
  && npm start` יעבדו על כל מכונה בלי שרת DB או קומפילציה נייטיבית. בנפח
  MVP (עשרות-מאות הרשמות) זה מספיק מהיר. אם הפיילוט מצליח, להחליף את
  `src/db.js` ל-Postgres זו עבודה מוכלת כי כל שאר הקוד מדבר רק עם הפונקציות
  שהמודול הזה מייצא.
- **שער האיכות הוא המוצר, לא רק פיצ'ר.** כל אתר עובר שלושה ספים אוטומטיים
  (DR מינימלי, ציון ספאם מקסימלי, תעבורה מינימלית — ר' `.env.example`).
  אתרים גבוליים נכנסים לתור בדיקה ידנית באדמין; אתרים גרועים מדי נדחים
  אוטומטית; אתרים טובים מאושרים אוטומטית בלי מגע יד אדם. זיהוי קטגוריה
  לא-ברור מוריד אוטומטית "אושר" ל"ממתין לבדיקה" (אף פעם לא הפוך).
- **סריקה רב-עמודית, לא רק עמוד הבית.** לכל אתר שעולה, `src/crawler.js`
  מנסה קודם `sitemap.xml` (אם אין — לינקים מעמוד הבית), ואז מביא עד 6
  עמודים (כותרת, meta description, H1 מכל אחד). זה נותן איתות הרבה יותר
  טוב לזיהוי קטגוריה/מילות מפתח אמיתיות מאשר עמוד הבית לבד. אין הרצת
  JavaScript (fetch רגיל, לא headless browser) — אתר SPA שכל התוכן שלו
  נטען בצד לקוח ייראה כמעט ריק. זו מגבלה ידועה, לא באג.
- **זיהוי קטגוריה הוא מילוני, לא NLP אמיתי.** `src/categorize.js` סופר
  הופעות של מילות מפתח מ-`src/niches.js` מול הטקסט שנסרק, ומחזיר גם רמת
  ביטחון (`high`/`low`/`none`). זה בכוונה גס וזול — התפקיד שלו הוא **למלא
  מראש** את מסך האישור למשתמש, לא לקבל החלטה סופית בעצמו. ביטחון `none`
  תמיד דוחף את האתר לבדיקה ידנית, גם אם שאר המדדים תקינים.
- **מודל אישור כפול (double opt-in).** התאמה לא חושפת פרטי קשר עד ששני
  הצדדים אישרו במפורש.
- **Matching v1 הוא זוגי בלבד**, לא מעגלי (A→B→C→A). מודל מעגלי דורש נפח
  משתמשים שאין בשלב הפיילוט — זה נשאר לגרסה 2.
- **הצעה אחת חדשה ליום לכל אתר, לא הצפה בהרשמה.** `src/scheduler.js` מריץ
  ברקע פעם ביום סבב התאמות (שנוגע רק באתרים שכרגע פנויים — ר' `src/matching.js`)
  ואחריו סבב בדיקות. גם בלי שרת cron חיצוני: הזמן האחרון שכל עבודה רצה
  נשמר ב-`data/scheduler-state.json`, כך שהפעלה מחדש של השרת לא מאפסת
  את השעון ולא גורמת להרצה כפולה.
- **וידוא שהקישור אכן באוויר — לא רק self-report.** אחרי ששני הצדדים
  מדווחים על כתובת העמוד שבו שמו את הקישור, `src/verifier.js` שולף את אותו
  עמוד ומחפש בפועל תג `<a>` שמצביע על הדומיין השני. בדיקה חוזרת (כל
  `VERIFICATION_RECHECK_DAYS` ימים) תופסת מקרה של "hit and run" — צד שמסיר
  את הקישור אחרי שכבר קיבל את שלו.
- **מניעת שימוש לא הוגן דרך ציון אמינות, לא רק שער כניסה.** לכל אתר נספרים
  `offered` (כמה הצעות קיבל), `verified` (כמה אומתו בפועל), `noShow` (כמה
  פעמים לא דיווח קישור בזמן), ו-`removedAfterReciprocation` (כמה פעמים
  הוריד קישור אחרי שהצד השני כבר העלה את שלו) — כל זה גלוי בלוח הניהול.
  התאמה שנתקעת יותר מ-`NO_SHOW_DAYS` ימים בלי דיווח קישור בוטלת אוטומטית
  ומשחררת את שני הצדדים לחזור לתור. v1 עדיין לא **חוסם** אוטומטית אתר עם
  ציון אמינות גרוע (זה נשאר להחלטה ידנית באדמין כרגע) — זה הצעד הבא הטבעי
  ברגע שיש מספיק נתונים אמיתיים כדי לקבוע סף הגיוני.
- **העלאה בקובץ CSV, לא XLSX אמיתי — החלטה מכוונת.** נבדקה תמיכה בקובצי
  Excel אמיתיים (חבילת `xlsx`/SheetJS), אבל `npm audit` העלה חולשת אבטחה
  ברמה גבוהה (prototype pollution + ReDoS) **בלי תיקון זמין** בחבילה הזו —
  מסוכן במיוחד כשהקובץ מגיע מהעלאה חיצונית לא מהימנה. לכן ההעלאה תומכת
  ב-CSV/טקסט בלבד (עמודת דומיינים אחת, עם או בלי כותרת). מי שיש לו קובץ
  Excel אמיתי פשוט שומר אותו כ-CSV לפני ההעלאה, או מדביק את רשימת
  הדומיינים ישירות בתיבת הטקסט.

## התקנה והרצה

```bash
cd link-exchange-mvp
npm install
cp .env.example .env
# ערכו את .env - לפחות ADMIN_PASSWORD
npm start
```

השרת עולה על `http://localhost:3000` (או ה-PORT מ-`.env`).
לוח הניהול: `http://localhost:3000/admin` — Basic Auth, שם משתמש כלשהו,
סיסמה = `ADMIN_PASSWORD`.

ברירת המחדל (`METRICS_PROVIDER=mock`) מייצרת ציוני DR/ספאם/תעבורה מדומים
אך יציבים (אותו דומיין תמיד מקבל אותם מספרים), כדי שתוכלו להריץ את כל
הזרימה מקצה לקצה בלי מפתח API. כל מספר מדומה מסומן בבירור "מדומה" בממשק.
באותו אופן, ברירת המחדל (`EMAIL_PROVIDER=mock`) לא שולחת מייל אמיתי —
כל התראה נרשמת ל-`data/notifications.json` ומוצגת בלוח הניהול.

## זרימת בדיקה ידנית מהירה

1. היכנסו ל-`/`, הזינו מייל, והדביקו/העלו כמה דומיינים (URL אמיתי לא
   נדרש לבדיקה — הציונים בכל מקרה מדומים, אבל הסריקה עצמה תנסה להגיע
   לאתר האמיתי; דומיין שלא קיים פשוט ייכשל בסריקה ויידחה או ייכנס
   לבדיקה ידנית, וזה תקין).
2. תגיעו לדשבורד האישי (`/s/<token>`) — הדף מתרענן אוטומטית עד שהסריקה
   מסתיימת, ואז מציג מסך אישור עם הקטגוריה שזוהתה לכל אתר. אשרו הכל.
3. אם אתר קיבל סטטוס "ממתין לבדיקה ידנית שלנו", אשרו/דחו אותו ב-`/admin`.
4. לחצו "הרץ סבב התאמות + שלח התראות עכשיו" ב-`/admin` (זה מה שקורה
   אוטומטית פעם ביום; הכפתור מריץ את זה מיידית לצורך בדיקה).
5. פתחו את דשבורד ה-`/s/<token>` של שני האתרים שהותאמו, ולחצו "מאשר/ת
   התאמה" בשניהם — בשלב הזה נחשפים פרטי הקשר. דווחו כתובת עמוד לכל צד
   (אפשר כל URL תקין לבדיקה).
6. לחצו "הרץ בדיקת no-show + אימות קישורים עכשיו" ב-`/admin` — אם הקישור
   באמת נמצא בעמוד שדווח, ההתאמה תעבור לסטטוס "מאומת — הקישורים חיים".
7. חזרו ל-`/admin` ותראו את המספר החשוב: **קישורים חיים ומאומתים**, וגם
   את טבלת האמינות לכל אתר.

## פרסום לכתובת ציבורית זמנית (Render, חינמי)

הסביבה שבה נבנה הפרויקט הזה חסומה ברשת ולא יכולה לחשוף אותו בעצמה
(לא tunnels כמו ngrok/cloudflare, לא דיפלוי ישיר ל-PaaS) — צריך לדחוף
את הקוד ולחבר אותו ידנית. זה לוקח כ-5 דקות:

**1. להעלות ל-GitHub** (אם אין לכם ריפו עדיין):

```bash
cd link-exchange-mvp
git init
git add .
git commit -m "Initial commit"
```

לכו ל-github.com → New repository → צרו ריפו ריק (בלי README) בשם
`link-exchange-mvp`, ואז:

```bash
git remote add origin https://github.com/<your-username>/link-exchange-mvp.git
git branch -M main
git push -u origin main
```

**2. לחבר ל-Render** (חינמי, בלי כרטיס אשראי):

1. היכנסו ל-[dashboard.render.com](https://dashboard.render.com) והתחברו עם GitHub.
2. **New +** → **Web Service** → בחרו את הריפו `link-exchange-mvp`.
3. הגדרות:
   - **Environment**: Node
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
4. תחת **Environment Variables** הוסיפו את המשתנים מ-`.env.example` (חשוב
   במיוחד: `ADMIN_PASSWORD` עם סיסמה אמיתית, ו-`BASE_URL` עם הכתובת
   שRender ייתן לכם — אפשר לעדכן אותו אחרי הדיפלוי הראשון).
5. **Create Web Service**. אחרי כמה דקות תקבלו כתובת כמו
   `https://link-exchange-mvp-xxxx.onrender.com`.

**אזהרה חשובה על התוכנית החינמית של Render**: הדיסק שם *ארעי* — אחרי
תקופת חוסר פעילות (כ-15 דקות) השירות "נרדם", ובהתעוררות מחדש הוא עלול
לאבד את קבצי `data/*.json` (כלומר את כל ההרשמות וההתאמות שנצברו). זה
בסדר לבדיקת דופק קצרה שאתם עוקבים אחריה, אבל לא לפיילוט של כמה שבועות
בלי השגחה. אם תרצו נתונים שלא נמחקים — הפתרון הכי פשוט הוא Persistent
Disk בתשלום ($1/חודש בערך) או מעבר ל-DB חיצוני חינמי (כמו Supabase);
תגידו לי אם תרצו שאבנה את זה.

## מה שבכוונה לא נכלל בגרסה הזו (ולמה)

- מעגלי החלפה (A→B→C→A) שמפחיתים את הדמיון ל-reciprocal linking קלאסי.
- זיהוי PBN/link-farm אוטומטי (IP/WHOIS/יחס תוכן-פרסום).
- אכיפת גיוון anchor text.
- הגבלת velocity (קצב קישורים חדשים לאתר בחודש).
- חסימה אוטומטית של אתר על סמך ציון אמינות נמוך (כרגע רק גלוי לאדמין,
  לא אוכף לבד).
- העלאת קובצי XLSX אמיתיים (הוסר בכוונה מסיבת אבטחה — ר' למעלה).
- אימות בעלות על דומיין (כרגע כל מי שמזין דומיין יכול "לטעון" לו — מספיק
  לבדיקת דופק, לא מספיק לפרודקשן).

כל אלה תלויים בנפח אמיתי כדי שיהיה טעם לבנות אותם — הם התוכנית לגרסה 2
ברגע שהפיילוט מוכיח שיש ביקוש בפועל (המדד: "קישורים חיים ומאומתים", לא הרשמות).

## סיכון שחשוב לזכור

גם עם matching זוגי בלבד ושער איכות, רשת של אתרים שמקשרים זה לזה בתדירות
לא-אקראית היא בהגדרה דפוס שגוגל יכול תיאורטית לזהות — הסיכון מצטמצם
משמעותית עם השער והאישור הכפול, אבל לא מתאפס. שווה לעקוב אחרי כמה מהאתרים
המשתתפים אחרי חודש-חודשיים ולוודא שלא רואים ירידות דירוג חריגות.

## מבנה קבצים

```
server.js                נתיבי Express, חיווט הכל יחד
src/db.js                 שכבת נתונים (JSON files) -- כולל submissions/sites/matches
src/pipeline.js            מריץ סריקה+קטגוריזציה+מדדים+שער איכות לכל אתר חדש (ברקע)
src/crawler.js             סורק רב-עמודי (sitemap-first, עד 6 עמודים)
src/categorize.js          ניחוש קטגוריה + חילוץ ביטויים (מילוני, לא NLP)
src/metrics.js             ספק מדדים (mock + תבנית ל-API אמיתי)
src/qualityGate.js         לוגיקת שער האיכות
src/matching.js            מנוע ההתאמה הזוגי
src/scheduler.js           עבודות רקע יומיות (drip + אימות)
src/emailer.js             שליחת התראות (mock + תבנית ל-Resend)
src/verifier.js            בדיקה בפועל שקישור קיים בעמוד שדווח
src/niches.js              רשימת הנישות הסגורה + מילות המפתח לזיהוי
src/util.js                עזרים (נרמול URL, ולידציה, פרסור רשימת דומיינים, Basic Auth)
views/                    תבניות EJS (index = הרשמה, submission = דשבורד אישי, admin = ניהול)
public/style.css           עיצוב RTL אחיד
data/                     קבצי הנתונים (נוצרים אוטומטית בהרצה ראשונה)
```
